@ABSTRACT 面對每日數百則資安新聞與持續新增的漏洞清單，企業資安團隊最困難的不是缺乏資訊，而是缺乏排序：哪一個漏洞「現在」最該修？本專題提出一套基於機器學習之跨平台 CTI 分析與決策支援平台，以 788 篇中英文情資建構長達 35 個月的語料，自動抽取 288 個 CVE，並對照 CISA KEV、FIRST EPSS、CVSS 與 MITRE CWE 四項公開資料，產出可解釋的風險分數與 P1–P3 修補優先級（含 24 小時／7 天／30 天處置期限）。實測顯示，本系統排序「已遭利用漏洞」的能力（交叉驗證 AUC 0.853）優於單用 CVSS（0.561）與單用 EPSS（0.827）；規則式分類在雙人標註之 held-out 語料上達 73% 準確率（Cohen's κ=0.818）。系統亦量化自身覆蓋缺口——語料僅涵蓋時間窗內 KEV 的 11%，並以「已知被利用但未收錄」清單呈現剩餘 631 筆，避免使用者誤以為清單即全部。平台以 FastAPI 與原生 JavaScript 實作，提供總覽、修補清單、即時評估與情資流四個工作區，讓部署商從「讀新聞」改為「看清單」。
@KEYWORDS 網路威脅情資；漏洞修補優先級；EPSS；KEV；CWE；可解釋風險評分

#1 1. 前言
面對層出不窮的資安事件，企業部署商（Deployer）——負責內部資產與修補分流的人——每天必須在極短的時間內回答同一個問題：今天先修哪幾個漏洞？本專題的出發點是觀察到實務上的三重落差。

#1 1.1 研究背景與動機
第一重落差是「情資量與處理量不對等」。The Hacker News 每月發布約 250 篇安全新聞，TWCERT/CC 與 iThome 持續產出在地情資，而中小型企業的資安編制通常僅一至三人。本專題語料橫跨 2024 年 1 月至 2026 年 11 月共 788 篇情資，涵蓋 741 件事件，其中標題含 CVE 者僅一成左右——絕大多數新聞並不直接告訴工程師「要修什麼」。

第二重落差是「嚴重度與利用風險不對等」。企業普遍以 CVSS 分數排序修補，但 CVSS 衡量的是漏洞本身的嚴重度，與「是否真的被攻擊」無關。本專題以 CISA KEV（已知被利用漏洞清單）作為「已遭實際利用」的事實依據，回測發現：僅用 CVSS 排序的交叉驗證 AUC 只有 0.561，幾乎等於隨機；換用 EPSS（利用機率）後提升至 0.827，本系統加權模型則達 0.853。換言之，只看 CVSS，有一半的修補順序是錯的。

第三重落差是「在地情資與全球模型的斷裂」。國際威脅情報平台多未收錄 TWCERT/CC 等台灣來源，本專題語料包含 164 篇台灣情資，其中 69 個 CVE 具有本地通報紀錄，可供在地企業優先檢視。

#1 1.2 問題定義
綜合上述觀察，本專題將問題定義為五個具體痛點。痛點一：情資量遠大於處理量，團隊只能憑印象挑選。痛點二：不知道哪個漏洞先修，CVSS 高分與實際利用脫節（CVSS-only AUC 0.561）。痛點三：修補期限沒有依據，合規要求的 24 小時／7 天／30 天缺乏客觀分級。痛點四：在地情資被忽略，台灣來源占比僅 21%，卻承載最貼身的風險訊號。痛點五：決策無法稽核——主管問「為什麼先修這個」時，黑箱模型給不出答案。五個痛點的共同根源，是「新聞、漏洞資料與企業資產」三套資訊彼此斷裂：新聞不帶資產情境、漏洞資料不帶利用狀態、資產清單不帶威脅訊號，部署商被迫在腦中自行組裝。

#1 1.3 專題目標與貢獻
本專題的核心價值在於：將 EPSS、KEV、CWE 等分散的公開資料，組裝成一份可執行、可稽核的修補優先清單，並誠實呈現系統的覆蓋邊界。具體貢獻有三：其一，以固定且公開的權重（50／30／12／8）建立可解釋評分，犧牲約 0.05 的 AUC 換取每一分都能說出理由；其二，落地 SSVC 決策框架，產出 P1–P3 與對應 SLA；其三，量化「沒看到什麼」——語料僅涵蓋時間窗內 KEV 的 11%，剩餘 631 筆以獨立清單呈現，避免將「我看到的」誤認為「全部」。

#1 2. 文獻探討
本專題建立在多項公開標準之上。台灣電腦網路危機處理暨協調中心（TWCERT/CC）定期發布在地漏洞公告與事件通報，是本研究台灣語料的主要來源之一[1]；iThome 資安新聞則提供具時效性的中文報導視角[2]。在決策框架方面，Spring 等人提出之利害關係人特定漏洞分類（SSVC）[3] 依「利用狀態、曝險、影響」決定處置優先序，本專題即以 Deployer 角色為設計對象，將其轉換為可程式化的規則。Jacobs 等人提出漏洞利用預測評分系統（EPSS）[4]，以機器學習預測漏洞於未來 30 天內被利用的機率，其論文指出以利用機率排序優於以 CVSS 排序，本專題的實測（AUC 0.827 對 0.561）與其結論一致。CISA 的已知被利用漏洞目錄（KEV）[5] 收錄已觀察到實際攻擊的漏洞，是本研究判斷「利用事實」的黃金標準；MITRE 的通用弱點列舉（CWE）[6] 提供弱點類型分類，本研究用於弱點類型篩選與情資佐證；FIRST 的 CVSS 3.1 [7] 則作為嚴重度補充來源。在修補管理實務上，NIST SP 800-40 [8] 建議以風險為基礎排定修補週期，本專題的 P1–P3 分級與其一致。標註品質方面，Cohen's kappa [9] 用以衡量雙人標註一致性。文獻回顧顯示：上述標準皆為「零件」，缺乏一個把利用事實、利用機率、嚴重度與在地情資整合成可執行工單的「組裝層」，此即本專題的切入點。

#1 3. 專題製作
#2 3.1 系統架構
系統採五層架構：資料來源層、語料層、情資對照層、決策層與介面層，如圖 1 所示。資料來源層整合 The Hacker News、TWCERT/CC 與 iThome 三類新聞來源；語料層以 SQLite 儲存 788 篇情資並進行去重；情資對照層將抽取出的 CVE 與 EPSS、KEV、CVSS、CWE 快照及企業資產清單比對；決策層執行規則分類、可解釋評分與修補優先級推算；介面層以 FastAPI 提供八個 REST 端點，前端採原生 JavaScript 與 Chart.js 渲染四個工作區。分層的理由是「每層可獨立驗證」：語料錯了只影響語料層測試，排序錯了不會污染分類器，錯誤可以被定位到層級而非整座系統。

#2 3.2 資料收集與語料建置
語料建置面對兩個實務限制：其一是來源不均——若依抓取順序取樣，語料會被最近兩個月塞滿（原始版本 77% 集中於近二月）；其二是 iThome 對深層頁面有 403 限制且 robots 規範禁止系統性抓取，故其僅能保留近期 50 篇。為此本專題採「分層取樣」：每月固定抽取 15 篇國際情資與 5 篇台灣情資，將 35 個月（2024-01 至 2026-11）鋪平，每月約 17–20 篇。語料分為兩層：平衡對照樣本 200 篇（台灣 100：國際 100，刻意 50:50）供台／國結構比較；自然語料 588 篇依真實發布比例收錄，反映真實分布。兩層並存的原因有二：只用自然語料時台灣僅占 21%，跨區比較會被國際量體淹沒；只用平衡樣本則會放大急迫性——實測 P1 占比在平衡樣本為 20%，自然語料僅 3%，相差約 6.7 倍。此偏差已於儀表板以「平衡對照樣本」註記揭露。

#2 3.3 CVE 抽取與外部情資對照
CVE 編號是把新聞、官方資料與企業資產串起來的唯一鍵。抽取流程為：以正規表示式比對 CVE-YYYY-NNNN 格式，並加入斷詞容錯——中文來源經斷詞後常出現「CVE 2025 5777」的拆開形式，需正規化還原為 CVE-2025-5777。788 篇語料共抽出 288 個不重複 CVE。每個 CVE 再對照四份外部快照：EPSS（911 筆，利用機率）、KEV（1,779 筆，已遭利用）、CVSS（704 筆，嚴重度）與 CWE（287 筆，弱點類型，其中 275 筆有值）。快照遵循「資料時效即時效」原則：API 回傳的 data_as_of 取最舊快照日期，避免以最新日期掩蓋舊資料。CVSS 的取值順序為文章優先、CVE.org 補齊——文章載明分數者以文章為準以利追溯，未載明者查詢 CVE.org（154 筆），仍無法取得者僅 2 筆，覆蓋率達 99.3%。

#2 3.4 規則式分類與可解釋風險評分
文章分類將情資分為四類：系統漏洞與修補對策（VULN）、惡意威脅與主動攻擊（MALWARE）、前瞻研究與治理（RESEARCH）與產業動態（OTHER）。分類器為一組有順序的正規規則：逐條比對標題與內文，第一條命中的規則決定類別，並隨結果回傳命中理由。選擇規則式而非深度學習的考量有二：其一，語料僅 788 篇，深度模型樣本不足；其二，可稽核性——每一篇的判斷都能指回一行規則，而權重模型是黑箱。分類完成後，文章以加權模型轉為 0–100 的風險分數：

@EQ 分數 = 100 × ( 0.50 × 嚴重度 + 0.30 × 利用機率 + 0.12 × 暴露程度 + 0.08 × CVE 具名 )　　(1)

其中嚴重度依類別與 CVSS 換算；利用機率在 CVE 已知時採用 EPSS 實測值，已知遭利用者直接計滿；暴露程度依資產清單與情資描述推斷。權重採固定值，任何人皆可重算驗證。值得說明的是，若以邏輯回歸重新擬合權重，交叉驗證 AUC 可達 0.897，但產品仍採用固定權重，犧牲約 0.05 的 AUC 換取「每個分數都能說出構成」。此取捨是本專題方法論的核心立場：在資安決策場景，可解釋比多零點零五的準確更值錢。

#2 3.5 修補優先級與曝險推斷
修補清單以 CVE 為單位聚合：取該 CVE 所有報導中的最高 CVSS 與最高 EPSS，並標記是否落入 KEV。基礎分級規則為：KEV 命中者直接列為 P1；EPSS 達 0.10 或 CVSS 達 9.0 者列為 P2；其餘為 P3。曝險偏移僅作用於 P2／P3：對外曝險升一級、內網降一級、未知不動；KEV 永不降級——已遭實際利用的漏洞即使在內網也須立即處理。SLA 對應為 P1 24 小時、P2 7 天、P3 30 天。現行語料的 288 個 CVE 分級結果為 P1 131 筆、P2 134 筆、P3 23 筆；曝險判定來源中，資產清單比對 105 筆、情資描述 16 筆、產品名推斷 6 筆，其餘 161 筆維持未知。曝險推斷採優先序設計：人工指定、資產清單、情資描述、產品名推斷依序取勝，確保每一級的升降都有可查的來源。

#2 3.6 覆蓋缺口分析
只呈現「看到的」會讓使用者誤以為清單即全部。系統以語料日期窗（2024-01-18 至 2026-11-13）為分母，取 KEV 加入日落在窗內的 711 筆，減去語料涵蓋的 80 筆，得到 631 筆未收錄，覆蓋率僅 11%，其中 81 筆與勒索軟體活動相關。這 631 筆因缺乏曝險與文章可追溯，刻意不併入主清單，而以「已知被利用但未收錄」獨立頁面呈現。此設計的意義在於把「系統邊界」本身變成可決策的資訊：使用者不只拿到一份清單，還知道清單外的風險輪廓。

#2 3.7 評估方法與結果
評估分三層。第一層是分類品質：以 100 筆 held-out 語料由兩人獨立標註、第三人依判定表裁決；兩人同意率 87%、Cohen's kappa 0.818，裁決後準確率 73%（多數類別基準 44%）。此數字取代早期 in-sample 的 91%——in-sample 是規則調參所用資料，不得對外引用。第二層是排序有效性：以「是否落入 KEV」為黃金標準，比較不同排序法的交叉驗證 AUC——本系統 0.853，僅 EPSS 0.827，純 CVSS 0.561；precision@10 為 1.00，即前 10 名全部命中已遭利用漏洞。第三層是時間切分回測：以 2026-05-27 為切點，測試窗口 273 筆（169 筆已標註）分類準確率 0.88、排序 AUC 0.87。須誠實揭露的限制有二：EPSS／KEV 快照為 2026 年 11 月版本，無法還原「當時」的利用機率；測試窗口樣本僅 169 筆，AUC 的抽樣誤差不可忽略。評估結果彙整如表 1，排序比較如圖 2。

#1 4. 創新性
本專題的創新不在發明新的預測模型，而在四個工程與方法上的選擇。
#2 4.1 以可解釋性為中心的評分取捨
主流做法追求排序指標最大化；本專題反其道而行，固定 50／30／12／8 權重，接受 AUC 從 0.897（重新擬合）降至 0.853 的代價，換取每個分數皆可逐項拆解。平台前端將因子貢獻與決策路徑以晶片方式呈現，主管質疑「為何是 P1」時，系統能回覆「KEV 命中＋對外曝險」而不需開啟黑箱。
#2 4.2 官方公開資料的組裝層
EPSS、KEV、CWE、SSVC 皆為公開標準，但散落各處、格式不一。本專題的貢獻是以 CVE 為鍵將其組裝成決策層：利用事實（KEV）、利用機率（EPSS）、嚴重度（CVSS）、弱點類型（CWE）與曝險（資產清單）在同一個資料結構中交會，並以 SSVC 的角色分工（Deployer）決定規則。此組裝的成效可驗證：排序 AUC 優於任一單一來源。
#2 4.3 在地化情資整合
國際平台對台灣來源覆蓋不足。本專題納入 164 篇台灣情資，並將 69 個具台灣通報紀錄的 CVE 標記為「本地通報」，在修補清單中可一鍵篩選；即時評估亦加入地區調整項。此設計讓在地企業得以跳過與自身無關的國際雜訊。
#2 4.4 覆蓋缺口的誠實揭露
多數工具只呈現「我看到的」。本專題以 KEV 為鏡，量化語料覆蓋僅 11%，並將 631 筆未收錄漏洞製成獨立清單。誠實呈現邊界本身就是一種功能：它把「未知的未知」轉換為可管理的已知風險輪廓。

#1 5. 實用性與競爭分析
#2 5.1 使用情境
平台面向三種日常工作流程。例行批次：每週進入「修補清單」，依 P1–P3 與 SLA 排定工單並匯出 CSV，此流程不經任何手動輸入。事件觸發：收到新情資或廠商通報時，使用「即時評估」輸入資產與控制項，取得分數、等級與處置劇本，並以 what-if 對照「加裝哪一項控制可降級」。情境校正：清單上的 CVE 若與自身環境不同（如內網、有 WAF），可自清單帶入評估覆寫等級。此外，「情資流」保留全部原文供追溯，「補漏」頁每月檢視一次覆蓋缺口。四種流程對應平台四個分頁。
#2 5.2 與現有工具的比較
本專題不與成熟商業產品全面競爭，而是在「新聞到工單」這一段提供輕量決策層。表 2 以行銷角度比較四類既有工具。相較之下，本專題的差異在於：產出物直接是帶 SLA 的修補工單、決策可稽核、並主動揭露自身覆蓋邊界。

#1 6. 預期效益與商業化
#2 6.1 產值預估
預估口徑採「目標客群 × 滲透率 × 年費」：目標客群設定為台灣中小型企業與學校之資安團隊，規模假設 200 家；採訂閱制，年費 40,000 元；滲透率假設 10%–15%（即 20–30 戶）。據此，2027 年度產值落於新台幣 80 萬元至 120 萬元區間（跨度 50%），屬保守估計：其中未計入教育授權、政府採購與客製化顧問收入。須標注之限制：滲透率為假設值，尚未有目標客群購買意願調研佐證，收斂該區間需於初版釋出後以試用申請數校正。
#2 6.2 差異化
差異化可驗證者有四。其一，決策可稽核：任一 CVE 的 P1 判定皆可回溯至規則與快照資料，驗證方式為點擊任一項目檢視決策路徑晶片。其二，在地情資整合：69 個 CVE 具台灣通報紀錄，驗證方式為「本地通報」篩選維度，此為表 2 中四類工具皆未提供的維度。其三，零門檻採用：開源核心加雲端一鍵部署，驗證方式為自原始碼重現部署流程之所需時間。其四，覆蓋邊界透明：定期產出 KEV 覆蓋報告（現為 11%），驗證方式為補漏頁之統計與快照日期。
#2 6.3 企業購買理由
就成本面：商業威脅情報服務年費以數萬美元計，本方案以開源核心加選擇性訂閱切入，試用零成本，決策者可用現有資安人力驗證價值再談預算；以每日節省一小時人工瀏覽新聞估算，一名工程師年工時節約即可涵蓋多年授權費用。就效益面：產出物直接是帶 SLA 的工單，排序能力經回測優於純 CVSS 流程（AUC 0.853 對 0.561），可量化為「錯修一筆的時間成本」之降低。就風險面：KEV 永不降級與覆蓋缺口揭露，降低「自以為都看到了」的誤判風險；此點以本專題實測的 631 筆未收錄缺口為佐證，惟尚缺決策者訪談，屬待補項目。
#2 6.4 行銷策略
策略一：開源社群與資安會議。受眾為資安從業者與學生；渠道為 HITCON、TWCERT 資安月；動作為釋出開源儲存庫並附免費示範站 QR Code；預期指標（假設值）為首月 500 次造訪、20 組試用申請。策略二：教育授權。受眾為大專資安課程；渠道為教師研習；動作為提供含 14 台示範資產的教學包；預期指標（假設值）為三所學校採用。策略三：內容行銷。受眾為中小企業 IT 主管；渠道為 LinkedIn 資安社群；動作為每週自動發布「本週 P1 戰情摘要」；預期指標（假設值）為三個月 1,000 次點閱、五組轉化諮詢。策略四：政府與法遵。受眾為機關資訊單位；渠道為共同供應契約；動作為以 SLA 分級對照表提案；預期指標（假設值）為一年內一件標案進入備標。

#1 7. 結論與未來發展
本專題以 788 篇情資、288 個 CVE 與四份官方快照，建構了從新聞到修補工單的完整決策鏈。其貢獻可歸納為四點：以固定權重保住可解釋性；以 SSVC 為骨架組裝 EPSS／KEV／CWE 公開資料；以台灣語料補強在地化；以覆蓋缺口報告守住誠實邊界。回測與標註評估顯示，排序能力（AUC 0.853）與分類品質（73%，κ 0.818）均優於簡易基線，且每一項數字的限制皆已揭露。
未來發展有四：其一，快照自動化——以排程器每日更新 EPSS／KEV，消除人工同步；其二，資產串接——以 CMDB 匯出取代示範資產，曝險判定覆蓋率可自 44% 提升；其三，混合智能——以大型語言模型為文章生成摘要與處置建議，保留規則層作為可稽核底座；其四，流程整合——產出 Jira 與 ServiceNow 相容工單格式，讓清單直通既有維運流程。此外，評估體系將隨語料擴充持續滾動：每新增一輪標註，即重新產出準確率、κ 與 AUC，確保論文外的每個版本都有與之對應的數據。本專題證明了：在資安決策中，「可解釋」與「夠準確」並非二選一，而是可以同時交付的工程目標——而這正是部署商在每一個修補窗口前，最需要的一份答案。
