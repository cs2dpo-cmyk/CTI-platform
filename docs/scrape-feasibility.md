# 語料擴充的抓取可行性評估

> 實測日期：2026-11-13。所有數字來自直接抓取，不是估算。

## 測試方法

對每個來源探測「歷史分頁能往回多深」，再依文章密度換算可抓筆數：

| 來源 | 探測方式 | 結果 |
|---|---|---|
| The Hacker News | Blogger JSON feed 的 `start-index` 參數 | `start=1` → 2026-11-13；`start=501` → 2026-09-16；`start=1001` → 2026-07-15 |
| iThome | 新聞列表 `?page=N` 逐頁測試 | page 1/2/5/20/50 正常；**page 55 起 403**（等 15 秒重試仍 403，page 1 仍 200 → 是深度上限，不是速率限制） |
| TWCERT | 公告列表 `lp-104-1-{n}-20.html` 的區塊編號 | 區塊 1 → 2026-11；區塊 10 → 2023-09；區塊 60 → 2019-12 |

## 各來源結論

### 1. The Hacker News（英文，可回溯最深）

| 項目 | 數值 |
|---|---|
| 可回溯範圍 | **無明顯上限**（`start-index` 可任意往回） |
| 密度 | 約 1,000 篇 ≈ 4 個月 → **約 250 篇／月** |
| 3 年可抓量 | 約 **9,000 篇**（遠超過需求） |
| 抓取成本 | 每次 50 篇，間隔 1.2 秒；3 年約 **45 次請求、2–3 分鐘** |
| 阻礙 | `/search` 頁面回 403，但 **JSON feed 可用**（現有爬蟲已在用） |

**結論：唯一能撐起 3 年時間軸的來源。**

### 2. TWCERT（中文，深度夠但量少）

| 項目 | 數值 |
|---|---|
| 可回溯範圍 | 至少到 **2019 年** |
| 密度 | 區塊 1→10（2023-09 到 2026-11）共 9 區塊 = 180 篇 / 38 個月 ≈ **4.7 篇／月** |
| 3 年可抓量 | 約 **165 篇** |
| 抓取成本 | 每區塊 20 篇，3 年約 **9–10 次請求** |
| 阻礙 | 無（目前爬蟲已在用） |

**結論：中文內容的主要來源，但每月不到 5 篇，撐不起每月 20 篇。**

### 3. iThome（中文，深度受限）

| 項目 | 數值 |
|---|---|
| 可回溯範圍 | **僅約 50 頁 ≈ 1 個月**（page 50 → 2026-10-14；page 55+ → 403） |
| 密度 | 約 42 篇／日（page 1→50 涵蓋 30 天） |
| 3 年可抓量 | **只有最近一個月**（約 1,200 篇） |
| 抓取成本 | 50 次請求可抓完整一個月 |
| 阻礙 | 深頁被 WAF 擋（不是 rate limit，換時間重試仍 403） |

**結論：無法回填歷史，只能供應近期樣本。**

## 對「700 筆、每月 20 篇」計畫的影響

原本的假設是三個來源平均供應，但實測後**不成立**：

| 來源 | 每月可貢獻 | 說明 |
|---|---|---|
| THN | 15–20 篇 | 唯一能任意回填 |
| TWCERT | 4–5 篇 | 全部收錄也只有這麼多 |
| iThome | 僅最近 1 個月 | 歷史不可得 |

### 可行方案

| 方案 | 組成 | 筆數 | 台灣占比 | 代價 |
|---|---|---|---|---|
| **A（建議）** | THN 15/月 + TWCERT 5/月，近一個月補 iThome | ≈700 | **約 29%** | 破壞現有 50:50 平衡 |
| B | 只做近 12 個月，三來源並用 | ≈240 | 約 45% | 時間軸太短，回測無意義 |
| C | 方案 A + 新增一個中文來源（資安人／網管人／科技新報） | ≈700 | 40–45% | 需再花 0.5 天探測新來源 |
| D | 維持 200 筆 | 200 | 50% | 時間軸偏差無解 |

### 時間軸本身的限制

即使方案 A，2025 年之前每月仍只有「THN 15 + TWCERT 5」，而 TWCERT 的 5 篇是**同一份公告的 5 篇**（品質高但主題集中）。趨勢圖會呈現「THN 主導、TWCERT 點綴」的形狀，這點必須在論文中說明。

## 建議

**方案 C**：先做 A，同時花半天探測一個新的中文來源。理由是：

1. 你的產品定位包含「台灣在地情資」，29% 的台灣占比說服力不足
2. 50:50 是現有簡報的賣點，掉到 29% 需要主動解釋
3. 新來源只需確認「有歷史分頁 + 文章密度」，半天可完成

## 抓取風險

| 風險 | 影響 | 對策 |
|---|---|---|
| WAF 封鎖（iThome 已發生） | 抓取中斷 | 每次間隔 2–3 秒、失敗重試 2 次、保存已抓進度 |
| 站方條款 | 內容使用爭議 | 只抓標題與摘要、標註來源、不做全文轉載 |
| 日期不可靠 | 時間軸錯誤 | 保留 `date_source` 欄位（現有機制），無日期者標記為 unknown |
| 抓取結果不可重現 | 別人驗不出 | 每次抓取產生 manifest（日期、筆數、來源版本），存入 `data/` |
